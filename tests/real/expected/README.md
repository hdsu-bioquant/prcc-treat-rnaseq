# Realistic qualification frozen baseline

`validation_checksums.sha256` is intentionally absent during initial development.

Maintainers freeze it only after the exact ENA FASTQs, the qualified GDC installation,
and one production-style execution profile have completed **two clean realistic runs** whose
generated `results/run/validation_checksums.sha256` files are byte-for-byte identical.

The frozen subset is generated by the normal pipeline and deliberately excludes BAMs,
MultiQC HTML, timestamped provenance, and environment-dependent metadata.

Partners do not regenerate this baseline. After it is frozen in a release, their realistic
qualification run is compared against the maintained file by `validate_results.py`.

See `tests/real/README.md` for the development/freeze and partner qualification procedures.
