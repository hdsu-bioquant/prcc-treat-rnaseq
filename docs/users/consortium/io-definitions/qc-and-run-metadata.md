# Consortium IO definition — QC and run metadata

## QC

Portable QC products are stored beneath `results/qc/` and summarize library/run processing using the maintained workflow QC steps, including FastQC/MultiQC-derived products and workflow-generated metrics where applicable.

QC is intended to support technical review; thresholds and cohort-level inclusion/exclusion decisions are not encoded here unless explicitly specified by a consortium analysis plan.

## Run metadata and provenance

Portable run metadata beneath `results/run/` records the standardized technical library manifest, effective run configuration/provenance, pipeline release identity, output-contract version, and deterministic validation information generated by the workflow.

The original user-supplied sample sheet is retained under `restricted/run/` rather than copied wholesale into the portable results package.

## Data-sharing boundary

The standard consortium transfer contains `results/` only. Source FASTQ paths, unrestricted copies of original sample annotations, and other potentially sensitive/local metadata are not part of the portable contract unless separately approved.
